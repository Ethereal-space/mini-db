## 已明确处理的材料差异

| 差异 | 本项目规则 |
| --- | --- |
| C-S6 的逻辑运算与 C-S41 的进阶分类 | AND、OR、NOT 和括号属于核心基础。 |
| G-P4 把优化列为可选，C-S5/S33/S34 给出优化教学 | 核心实现常量比较折叠与布尔化简，并验证前后等价。 |
| C-S35 将持久化列入扩展方向，G-P6/P8 要求重启恢复 | Catalog 与数据的正常关闭重启恢复属于核心。 |
| C-S9 展示 FLOAT 和算术 Token | Lexer 识别；核心语义拒绝 FLOAT，完整算术与新类型使用扩展。 |
| C-S11 展示 `==` | 项目兼容 `== → =`、`<> → !=`，保留原 lexeme。 |
| C-S16 的优先级文字与产生式可能产生不同解读 | 采用产生式：`NOT age=18` 为 `NOT(age=18)`，用 AST 测试冻结。 |
| D-S19/S20 以骨架说明整条链 | 项目补齐真实 Semantic、Plan、Executor、Page、Buffer 与持久化，禁止 dummy row。 |
| D-S11/S12 介绍 B+ 树 | 核心执行使用 SeqScan；B+ 树是 C-E09 的隔离实验。 |

## 任务卡引用要求

每张 Markdown 卡与 Word 卡必须保留源 JSON 中的 `course_basis`/“课程依据”。新增要求若不是原材料直接规定，应写成“本项目约定”，并在 PROJECT_SPEC 或接口文档中给出可测试定义。`docs/tasks/catalog.json` 是任务编号、卡片路径和课程依据的机器可读入口。
