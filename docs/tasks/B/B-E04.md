# B-E04 UPDATE 语义检查与更新计划

## 课程依据

G-P4；C-S6、C-S35；D-S17

UPDATE 是课程列出的可选 SQL。本任务只负责绑定和计划，真实行更新由执行器与存储扩展配合。

## 任务目标

检查UPDATE的表、SET列和WHERE，拒绝重复目标列。SET右侧使用核心Expr并绑定为BoundExpr，赋值表达式dtype必须等于目标dtype；按目标index排序输出assignments。执行器依据同一旧行同时求值全部赋值。编译无写副作用。

## 输入输出

输入是手工构造或前端产生的冻结 AST、Catalog 元数据与版本化扩展信封；输出是 Bound AST、Logical Plan、优化后 Plan 或结构化语义/计划错误。不得读写真实数据页。

## 公共接口

`CatalogPort`、`CatalogRepositoryPort` 与 `CompilerPort.compile/optimize`；输入为冻结 AST/扩展信封，输出为 Bound 节点、Plan 节点或版本化扩展信封。

扩展不得直接改变冻结 AST、Bound AST、Plan 或 Protocol；跨层扩展统一使用 `ExtensionStatement`、`BoundExtension`、`ExtensionPlan(feature, version, payload, span)`。

## 实现步骤

1. 固定 update/v1 节点及赋值数组快照。
2. 完成重复列、类型和条件绑定，再构造保留身份的子树。
3. 用 Fake 证明合法和非法 UPDATE 编译都没有存储副作用。

## 预期代码结构解释

- bind_assignments：先检测重复Identifier，再按schema绑定每个目标index与右侧表达式，允许列引用、字面量及核心类型合法表达式。所有右值都针对旧行布局。
- build_update_plan：ExtensionPlan(update,1)的payload={table,assignments,child}；赋值项固定{index,expr}，expr是Bound节点JSON编码。child为保留RID的SeqScan或Filter。
- validate_update：校验版本、WHERE为BOOL、赋值dtype匹配与源span；不支持一般算术时明确拒绝其节点，不能靠执行器强转。
- 易错点：更新计划不能用 Project 丢失 RID；绑定成功不代表存储具备变长行迁移。
- 整合范围：B 可独立验收；完整 UPDATE 组合 A-E01、B-E04、D-E02、C-E07，并集中对齐同一 update/v1 版本。

## 测试用例

1. `test_update_binds_assignments_by_schema`

   - 输入：UPDATE student SET age=21,name='李四' WHERE id=1。
   - 必须断言：assignments 依 index 为 1、2 排序；where 的 id index=0；child 保留扫描身份。

2. `test_update_duplicate_assignment_rejected`

   - 输入：SET age=20,AGE=21。
   - 必须断言：Semantic 错误指第二次赋值，不能静默保留最后值。

3. `test_update_type_and_unknown_column`

   - 输入：SET age='20' 或 SET score=1。
   - 必须断言：分别拒绝类型和未知列，给出对应 SET Span，无写调用。

4. `test_update_without_where_has_full_scan`

   - 输入：UPDATE student SET age=0，无 WHERE。
   - 必须断言：计划 child 为全表扫描，无 Filter 与 Project；版本字段为 1。

5. `test_update_column_swap_binding`

   - 输入：INT列a、b，SET a=b,b=a。
   - 必须断言：assignments为index0→BoundColumn1、index1→BoundColumn0，dtype均INT，无写调用。
