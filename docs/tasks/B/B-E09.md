# B-E09 Plan JSON、S 表达式与 EXPLAIN 输出

## 课程依据

G-P3、G-P7；C-S30、C-S32、C-S35、C-S42；D-S10

材料允许以树、JSON、S 表达式展示计划。本任务增加可机器检查的序列化和说明，不执行 SQL。

## 任务目标

为所有核心计划节点与 Bound 表达式提供稳定 JSON 和 S 表达式输出。JSON 带 format_version=1、node_kind、fields 和 children，只包含 JSON 基本值；EXPLAIN 可同时展示原计划、优化计划及规则命中，编译和输出均不得执行 DML。

前置缺失时，只能在本成员授权目录内补齐最小必要部分；跨成员能力使用冻结 Protocol 和 tests 中的 Fake。

## 输入输出

输入是手工构造或前端产生的冻结 AST、Catalog 元数据与版本化扩展信封；输出是 Bound AST、Logical Plan、优化后 Plan 或结构化语义/计划错误。不得读写真实数据页。

## 公共接口

`CatalogPort`、`CatalogRepositoryPort` 与 `CompilerPort.compile/optimize`；输入为冻结 AST/扩展信封，输出为 Bound 节点、Plan 节点或版本化扩展信封。

扩展不得直接改变冻结 AST、Bound AST、Plan 或 Protocol；跨层扩展统一使用 `ExtensionStatement`、`BoundExtension`、`ExtensionPlan(feature, version, payload, span)`。

## 实现步骤

2. 添加中文、引号与控制字符转义测试。

## 预期代码结构解释

- plan_to_dict：逐节点显式映射字段，枚举转字符串、tuple 转数组、Span 转位置对象；禁止直接序列化 __dict__ 泄漏内部状态。
- format_sexpr：对名称、字符串用确定性转义，清楚表示 Filter 谓词与 Project 索引。
- explain_bundle：聚合原计划、优化计划和规则记录；无 Executor、Storage 或表号分配调用。
- 易错点：可序列化不等于允许任意反序列化执行；本任务不提供从不可信 JSON 直接运行计划的入口。
- 整合范围：B 输出格式可独立验收和使用；用户从 CLI 输入 EXPLAIN 还需 D-E01 和集中装配的编译路径接入。

## 测试用例

1. `test_json_roundtrip_contains_only_primitives`

   - 输入：含 '张三' 字符串与 Span 的 SELECT 计划。
   - 必须断言：json.dumps/loads 成功且信息相等，中文恢复原值，无对象地址。

2. `test_formats_cover_all_core_plans`

   - 输入：CREATE、INSERT、SELECT、DELETE 各一棵计划。
   - 必须断言：JSON node_kind 与 S 表达式根名正确；DELETE 子树保留 Scan，不漏字段。

3. `test_explain_is_deterministic`

   - 输入：同一原计划与优化计划格式化两次。
   - 必须断言：输出逐字相同，format_version=1，优化规则名称可查。

4. `test_explain_never_executes_mutation`

   - 输入：EXPLAIN 的目标为 INSERT 和 CREATE，写方法设置为一调用就失败。
   - 必须断言：输出计划成功，execute/allocate/register 计数全部为 0。
