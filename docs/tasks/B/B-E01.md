# B-E01 可注册优化规则框架

## 课程依据

G-P4；C-S33、C-S35、C-S41；D-S10

PPT 提出规则优化和可扩展设计；可注册框架是项目扩展，不是实现核心两条规则的前置条件。

## 任务目标

把固定优化分支改成有名称、有适用条件、有优先级的局部规则列表，支持开启和关闭规则、记录命中及达到固定点。规则失败暴露真实异常；为互相反复改写的规则设置轮次上限并报告问题，防止优化挂死。

## 输入输出

输入是手工构造或前端产生的冻结 AST、Catalog 元数据与版本化扩展信封；输出是 Bound AST、Logical Plan、优化后 Plan 或结构化语义/计划错误。不得读写真实数据页。

## 公共接口

`CatalogPort`、`CatalogRepositoryPort` 与 `CompilerPort.compile/optimize`；输入为冻结 AST/扩展信封，输出为 Bound 节点、Plan 节点或版本化扩展信封。

扩展不得直接改变冻结 AST、Bound AST、Plan 或 Protocol；跨层扩展统一使用 `ExtensionStatement`、`BoundExtension`、`ExtensionPlan(feature, version, payload, span)`。

## 实现步骤

1. 先把 B-B06 两条规则移入注册表，保持原结果。
2. 加入 enabled_names、轮次上限和重复名称检查。
3. 写关闭规则及故意振荡规则测试，说明固定点终止条件。

## 预期代码结构解释

- Rule(name,priority,apply)：apply 接受不可变节点，未匹配返回原节点，匹配返回新节点；不接触 Catalog 和磁盘。
- RuleOptimizer.run：按优先级与名称稳定排序，完成一轮后比较结构是否变化；固定点返回，超限报 Optimizer 错误。
- RuleTrace：记录规则、轮次、前后节点摘要和变化数；仅统计结构真正改变的命中，不把重复访问算优化。
- 易错点：返回一个值相同的新对象不等于语义变化；终止不能仅比较对象地址。
- 整合范围：该扩展可单独完成和使用，不改变 CompilerPort 或 Plan；整合只选取 B 的已验收扩展分支。
