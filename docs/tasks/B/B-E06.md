# B-E06 JOIN 名称绑定与列名歧义检查

## 课程依据

G-P4；C-S6、C-S26、C-S35；D-S9、D-S10

JOIN 是课程可选语言能力。本任务处理双表 INNER JOIN 的作用域与类型，不把 B+ 树或代价选择当成前提。

## 任务目标

建立表别名到 schema 的作用域；限定列名按别名解析，无限定名只有唯一匹配才合法。输出左行加右行的拼接布局，右列索引增加左表列数。ON 必须为 BOOL；首版限定双表 INNER JOIN，拒绝未声明别名和同名别名。

## 预期代码结构解释

- JoinScope：保存 alias、TableMeta、offset；列解析返回原列类型与拼接 index，不修改 TableMeta.ordinal。
- resolve_join_column：有前缀先匹配 alias，无前缀搜全部表；零匹配为缺列，多匹配为歧义，不能任取第一项。
- build_join_plan：join/v1 JSON fields 含 left、right、predicate、output_schema；谓词和投影使用统一拼接布局。
- 易错点：右表 ordinal=0 不代表 JOIN 输出 index=0；两套索引必须区分。

## 测试用例

1. `test_qualified_columns_use_join_offsets`

   - 输入：s(id,name) JOIN e(id,course) ON s.id=e.id。
   - 必须断言：s.id index=0，e.id index=2；类型均 INT，ON 为 BOOL。

2. `test_unqualified_duplicate_is_ambiguous`

   - 输入：两表都有 id，SELECT id。
   - 必须断言：Semantic 歧义错误列出两个候选别名，不产生计划。

3. `test_unique_column_can_be_unqualified`

   - 输入：只有 e 表有 course，SELECT course。
   - 必须断言：绑定为拼接 index=3，名称和 VARCHAR 类型正确。

4. `test_alias_and_join_predicate_errors`

   - 输入：重复别名 s、引用 x.id、ON s.id。
   - 必须断言：分别拒绝别名冲突、未知别名、非 BOOL 条件，各 Span 精确。
