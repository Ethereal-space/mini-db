# B-B03 SELECT 与 DELETE 名称绑定

## 课程依据

G-P3、G-P5、G-P8；C-S24、C-S25、C-S26；D-S10、D-S14、D-S17

课程要求表列存在性检查和名称绑定；本项目核心只有单表，因此不处理 JOIN 歧义与限定列名，相关能力留在 B-E06。

## 任务目标

把 SELECT 投影列和 WHERE 中的标识符绑定到同一 TableMeta 的列序号，保留名称、类型和源 Span。SELECT * 展开为 schema 顺序，显式列序必须保持用户书写顺序；允许重复投影列。DELETE 的 WHERE 使用同样的名字绑定，绑定结果保留原表信息，为后续基于 RID 删除提供依据。任何缺表缺列必须在生成可执行计划前报告。

## 实现步骤

1. 建立 id/INT/0、name/VARCHAR/1、age/INT/2 的固定 schema，给每个标识符不同 Span 以验证错误归属。
2. 实现 resolve_column 和星号展开，再将同一绑定函数用于 SELECT 与 DELETE 条件。
3. 用恶意 FakeCatalog 让所有写方法一调用便失败，证明名字绑定只读；检查 AST 未原地替换为 Bound 节点。

## 预期代码结构解释

- resolve_column(name,table,span)->BoundColumn：从规范列名索引找 ColumnMeta，返回 index=ordinal、name、dtype 和原 Span；未知名抛 Semantic 错误并明确表名。该函数不扫描任何数据行。
- bind_projection(columns,table)：None 表示星号并展开所有 ordinal；显式列名逐项 resolve，保留顺序和重复。结果 indices 与 names 长度相等，不能用 set 去重或排序。
- bind_select/bind_delete(stmt,catalog)：首先绑定表，再访问 projection 和 where；WHERE 递归处理每个 Identifier。DELETE 保留 TableMeta，不产生 Project；整体过程禁止调用发号、注册或存储。
- 易错点：投影顺序不等于 schema 顺序；WHERE 的 age 仍指原行第 2 列，不能因 SELECT 只取 name 就变为索引 0。
- 整合范围：B 可独立完成单表绑定；B-B04 负责条件类型，B-B05 构造计划。D-B02 按原行列序求值再投影，D-B04 使用保留的 RID 删除。

## 测试用例

1. `test_resolve_column_returns_ordinal_type_and_span`

   - 输入：查询 student 的 AGE，源 Span 为 offset 7..10。
   - 必须断言：BoundColumn 为 index=2,name='age',dtype=INT，Span 仍为 7..10；无扫描和写方法调用。

2. `test_select_star_expands_schema_order`

   - 输入：SELECT * 的 AST，table.columns 顺序为 id,name,age。
   - 必须断言：绑定投影 indices=(0,1,2)，names=('id','name','age')，没有丢失任何列。

3. `test_projection_preserves_order_and_duplicates`

   - 输入：SELECT name,id,name FROM student。
   - 必须断言：indices=(1,0,1)，names=('name','id','name')；原 AST 保持不变。

4. `test_unknown_table_and_column_keep_locations`

   - 输入：分别引用缺表 ghost、投影 score、WHERE score>0，各节点 Span 不同。
   - 必须断言：分别在对应表或列 Span 产生 Semantic 错误；消息含 ghost 或 score；无部分可执行计划返回。

5. `test_delete_binds_predicate_to_original_table`

   - 输入：DELETE FROM student WHERE age>=18 的手工 AST。
   - 必须断言：Bound DELETE 保留同一 table_id 与 first_page_id，条件左操作数 index=2；不带投影，Catalog 状态不变。
