# B-E05 ORDER BY 与 LIMIT 语义和计划

## 课程依据

G-P4；C-S6、C-S35；D-S10

ORDER BY 是课程扩展，LIMIT 是项目补充。本任务规定排序键、数量边界与算子顺序，不改变核心 SELECT 计划。

## 任务目标

绑定单表 ORDER BY 的列序号和 ASC/DESC，允许排序使用未投影列；LIMIT 必须为非负 INT 常量。扩展计划逻辑顺序为 Scan→Filter→Sort→Limit→Project，从而在丢弃列前完成排序。同键保持扫描顺序，首版不支持 OFFSET。

## 测试用例

1. `test_order_by_non_projected_column`

   - 输入：SELECT name ORDER BY age DESC LIMIT 2。
   - 必须断言：age 绑定 index=2；树为 Project(Limit(Sort(Scan)))，Sort 在投影前。

2. `test_limit_zero_is_not_absence`

   - 输入：LIMIT 0 与无 LIMIT。
   - 必须断言：前者存在 count=0 节点并输出空；后者没有限制节点。

3. `test_order_and_limit_validation`

   - 输入：ORDER BY score；LIMIT -1；LIMIT 1.5。
   - 必须断言：分别报未知列、负数量、非 INT，错误保留各自 Span。

4. `test_reference_order_is_stable`

   - 输入：(1,'A',20),(2,'B',22),(3,'C',22)，降序取 2。
   - 必须断言：参考输出 [('B',),('C',)]，同龄保持原扫描顺序。
