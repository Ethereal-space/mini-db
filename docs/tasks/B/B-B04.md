# B-B04 类型推导与 Bound AST

## 课程依据

G-P3、G-P5；C-S20、C-S24、C-S27、C-S28；D-S10、D-S17

课程要求类型一致性与表达式结构。BOOL 仅用于条件、禁止隐式真值转换和链式比较是本项目核心边界；FLOAT 字面量能被 Lexer 识别但核心语义仍拒绝。

## 任务目标

递归地把 Literal、Identifier、UnaryExpr、BinaryExpr 转为带类型的 Bound 节点。INT 支持 =、!=、<、<=、>、>=；VARCHAR 核心支持 =、!=；比较结果为 BOOL。AND、OR 的两侧和 NOT 的操作数必须为 BOOL，WHERE 根节点也必须为 BOOL。先绑定整棵树再进行优化，不能让恒假分支掩盖缺列或类型错误。

## 预期代码结构解释

- bind_expression(expr,table)->BoundExpression：按节点种类递归，先绑定子节点再查询类型规则；保留每个节点 Span。Literal 的类型根据真实值确定，核心拒绝 float、None 和外来节点。
- infer_binary(op,left_type,right_type,span)：使用集中规则表返回 BOOL 或报错。跨 INT/VARCHAR 比较拒绝，逻辑运算不使用 Python 的任意对象真值语义；规范运算符沿用契约。
- require_predicate(bound,span)：只接受 dtype=BOOL；NOT 构成 BoundUnary，其 operand 可以是 BoundBinary 比较。类型推导不重排优先级，必须保留 A 按 C-S16 文法得到的 AST 结构。
- 易错点：NOT 与比较的结构以 C-S16 文法为准：NOT age=18 是 NOT(age=18)。语义分析不应根据 PPT 那行不一致的优先级文字另行改树。
- 整合范围：独立验收检查 Bound 树与类型规则；D-B01 对相同规则求值。扩展新类型必须走独立扩展基线，不能改冻结核心 DataType。

## 测试用例

1. `test_integer_comparison_matrix`

   - 输入：INT 字面量 1、2 分别使用六种比较运算符。
   - 必须断言：每项结果 dtype=BOOL，两侧 dtype=INT，运算符和 Span 保留，输入 AST 不变。

2. `test_string_equality_and_type_mismatch`

   - 输入：'张三'='张三'；'a'!='b'；age='18'；name< 'z'。
   - 必须断言：前两项为 BOOL；后两项按核心规则拒绝，错误指向比较表达式并说明两侧类型或不支持的操作。

3. `test_not_preserves_comparison_subtree`

   - 输入：手工 AST 为 NOT(age=18) OR age>20 AND name!='Tom'。
   - 必须断言：根为 OR，右为 AND，左为 NOT 且其子为比较；所有逻辑结果 BOOL，age 的 index 均为 2。

4. `test_where_rejects_non_boolean_and_float`

   - 输入：WHERE age；WHERE 1 AND age=18；WHERE age=3.14。
   - 必须断言：依次拒绝非 BOOL 根、非 BOOL 逻辑操作数和核心不支持的 FLOAT；Span 对应实际问题节点。

5. `test_binding_checks_unreachable_branch`

   - 输入：WHERE 1=0 AND missing_column=1。
   - 必须断言：仍报告 missing_column，不得提前常量化为 FALSE 后接受；优化器未被调用。

## 理解考试与小修改

- 讲解题：为什么 WHERE 1 不能直接沿用 Python 的 bool(1)？
- 答案要点：项目的 SQL 类型规则要求 WHERE 为 BOOL；隐式转换会让 Parser、语义与运行时各有一套规则，并使错误输入被错误接受。
- 现场小修改：为 VARCHAR 排序写一个当前应拒绝的回归测试，解释若以后开放，需要同步类型规则和 D 求值规则，而非只删掉错误分支。
