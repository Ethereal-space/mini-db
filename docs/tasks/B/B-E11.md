## 输入输出

输入是手工构造或前端产生的冻结 AST、Catalog 元数据与版本化扩展信封；输出是 Bound AST、Logical Plan、优化后 Plan 或结构化语义/计划错误。不得读写真实数据页。

## 公共接口

`CatalogPort`、`CatalogRepositoryPort` 与 `CompilerPort.compile/optimize`；输入为冻结 AST/扩展信封，输出为 Bound 节点、Plan 节点或版本化扩展信封。

扩展不得直接改变冻结 AST、Bound AST、Plan 或 Protocol；跨层扩展统一使用 `ExtensionStatement`、`BoundExtension`、`ExtensionPlan(feature, version, payload, span)`。

## 预期代码结构解释

- edit_distance：使用动态规划，两行空间计算插入、删除、替换成本；ASCII casefold 后比较。
- suggest_names：过滤距离>2 的项，去重并排序后取前三；空集合输出空建议。
- enrich_name_error：在原 Semantic 错误上附加建议文本，保留原 Span 和原因，不把候选当作成功绑定。
- 易错点：自动纠正并执行可能读取或修改用户没有指定的对象；本任务只提供可解释的建议。
- 整合范围：模块内即可完整验收，CLI 只需照常展示已有错误；不要求 A 改 Parser，不需要 C 或 D 新接口。

## 测试用例

1. `test_distance_known_examples`

   - 输入：name/nmae、age/age、age/ages。
   - 必须断言：普通编辑距离分别为 2、0、1；不把交换算一次操作。

2. `test_suggestions_rank_and_limit`

   - 输入：输入 cat，候选 cut、bat、car、dog。
   - 必须断言：距离 1 候选按名称输出 bat、car、cut，最多三项。

3. `test_suggestions_do_not_cross_table_scope`

   - 输入：student 只有 name；其他表有 score；student 查询 scor。
   - 必须断言：不能提示 score；仍为未知列错误，保留原 Span。

4. `test_suggestion_never_accepts_bad_sql`

   - 输入：SELECT nmae FROM student，存在 name。
   - 必须断言：错误消息建议 name，但 compile 仍失败，Planner 和 Executor 调用均为 0。
