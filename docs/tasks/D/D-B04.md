# D-B04 删除执行器与影响行数

## 课程依据

G-P5、G-P6、G-P8；C-S6、C-S43；D-S17

将DeletePlan输出行的RID交给存储标记删除，随后查询跳过tombstone。

## 任务目标

执行DeletePlan.child，逐行读取RID并调用mark_delete。只有成功标记的行计数；无WHERE删除全部可见行；空匹配返回0。扫描复制行后已解除页pin，因此允许删除修改同页。结束后flush一次，异常关闭算子。

## 实现步骤

1. 构造同值不同RID行，证明按物理RID删除。
2. 实现无WHERE、全不匹配和部分匹配。
3. 失败注入检查close和flush行为，不伪造事务性保证。

## 预期代码结构解释

- execute_delete：以try/finally控制child生命周期；对每个可见StoredRow调用mark_delete(table,rid)。不按投影值反查，也不按业务id假设唯一。
- affected_rows：只对已成功删除记录增加；核心重复调用mark_delete对已删除槽幂等，但一次scan不应重复输出同一RID。
- 删除与扫描：Fake应模拟删除标志而不是从正在迭代的list中remove；真实存储同样保留slot编号，下一条查询的scan跳过已删除记录。
- 易错点：边迭代边从Python列表移除会跳过相邻行；tombstone恰好避免slot重编号。
- 整合范围：Fake由D维护删除位；C-B03、C-B06完成后集中验收重启仍已删除。
