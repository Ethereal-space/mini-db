## 预期代码结构解释

- UpdateExecutor：payload按公共v1字段解码；目标快照仅包含原匹配行；赋值使用旧tuple同时求值，成功后一次提交新tuple。
- UpdatePort.update_row(table,rid,values)->RID为本地扩展Protocol；C同名方法可直接适配。接收new_rid用于日志；当前不支持更新中的并发或索引自动维护。
- 易错点：行迁移是否保持RID要遵守C扩展协议，不得由D猜测。
- 整合范围：本模块独立完成；全链路需A-E01、B-E04、C-E07和共同payload版本。

## 测试用例

1. `test_de02_swap`

   - 输入：旧(a,b)=(1,2)，SET a=b,b=a
   - 必须断言：新值(2,1)。

2. `test_de02_none`

   - 输入：条件无命中
   - 必须断言：update调用0，影响0。

3. `test_de02_error`

   - 输入：赋值求值失败
   - 必须断言：该行无update调用。

4. `test_de02_rid`

   - 输入：匹配两不同RID
   - 必须断言：各调用一次，RID不混淆。

5. `test_de02_relocation_snapshot`

   - 输入：多页3个原匹配RID；更新使行迁到更后页，Fake会在新扫描中返回新行。
   - 必须断言：先完成scan再update；每个原RID仅更新一次；影响3行，返回新RID被记录，无重复处理。
