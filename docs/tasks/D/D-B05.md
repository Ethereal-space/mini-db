# D-B05 执行服务 Trace 与结果格式

## 课程依据

G-P6、G-P7；C-S42；D-S10、D-S19、D-S20

统一结果和执行错误，支持观察完整链路。上游Token等事件由integration收集，本任务只产生执行事件。

## 任务目标

ExecutionService实现ExecutorPort.execute，仅分派Plan；查询收集列名与行tuple，命令返回影响行数。TraceEvent使用stage/detail记录算子、行数、RID和缓存快照，不冒充编译器事件。格式器把结果转换为可读文本，中文保持完整，数据包含竖线和换行时可转义展示。

## 前置任务

D-B01至D-B04。

前置缺失时，只能在本成员授权目录内补齐最小必要部分；跨成员能力使用冻结 Protocol 和 tests 中的 Fake。

## 输入输出

输入是手工 Plan、冻结 Bound 表达式与注入的 Fake/真实端口；输出是 ExecutionResult、格式化结果、Trace 或结构化执行错误。不得自行解析 SQL、猜测 schema 或绕过 StoragePort。

## 公共接口

`ExecutorPort.execute(plan) -> ExecutionResult` 与 `ApplicationPort.execute(source, trace)`；只消费冻结 Plan/扩展信封和注入端口，不直接导入其他成员实现。

扩展不得直接改变冻结 AST、Bound AST、Plan 或 Protocol；跨层扩展统一使用 `ExtensionStatement`、`BoundExtension`、`ExtensionPlan(feature, version, payload, span)`。

## 实现步骤

1. 先分派核心六类Plan树并加未知Plan拒绝。
2. 设计纯函数格式器与中文/空结果样例。
3. 给Trace回调加隔离，两个执行结果不共享可变事件列表。

## 预期代码结构解释

- ExecutionService.execute：按明确Plan类型建立算子或命令执行器，不调用parse也不拼接SQL；在finally释放打开的算子。
- ExecutionResult：查询columns和rows宽度一致；命令columns/rows为空；affected_rows为非负整数；trace是独立事件序列，不写入全局共享列表。
- format_result：负责表头、行、条数与错误文字，不负责IO与业务决策。保留字符串值；格式化不应修改原Result。错误由CLI最外层展示，库层不直接print。
- 易错点：不要在D中造Token或AST日志。完整Trace由装配层调用真实A/B阶段并合并事件。
- 整合范围：独立测试只使用手工Plan和Fake；完整阶段Trace由小组integration负责。 TOKEN/AST是批次事件，integration只附到首个结果；每条编译与执行事件单独收集，不重复附加到后续结果。
