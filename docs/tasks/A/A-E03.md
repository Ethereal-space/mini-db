# A-E03 DISTINCT 语法扩展

## 课程依据

C-S35、C-S40；D-S10、D-S17

C-S40 将 DISTINCT 用作现场修改示例；项目将其列为独立扩展，核心不承诺去重执行。

## 任务目标

支持 SELECT DISTINCT * 或列清单，返回 distinct v1，payload={query}，query 是不含 DISTINCT 的核心 SelectStmt 编码。只接受紧跟 SELECT 的一个 DISTINCT，不把它误当列名；与其他扩展的组合另做兼容整合。

## 输入输出

输入是 UTF-8 SQL 文本或冻结 Token 序列；输出是冻结 Token/AST、结构化诊断或版本化 `ExtensionStatement`。不得查询 Catalog、访问存储或执行 SQL。

## 公共接口

`FrontendPort.parse(source: str) -> list[Statement]`；核心产物只使用冻结的 Token、AST、Span 与错误类型，扩展产物使用 `ExtensionStatement(feature, version, payload, span)`。

扩展不得直接改变冻结 AST、Bound AST、Plan 或 Protocol；跨层扩展统一使用 `ExtensionStatement`、`BoundExtension`、`ExtensionPlan(feature, version, payload, span)`。

## 实现步骤

1. 记录 distinct v1 的最小 payload 与边界。
2. 插入单一可选关键字分支，不复制 SELECT Parser。
3. 比较开启扩展前后的普通 SELECT AST，排除回归。

## 预期代码结构解释

- SELECT 入口：在投影解析前检查 DISTINCT，记录扩展标记后复用原核心逻辑。
- 包装函数：只有出现 DISTINCT 才返回 ExtensionStatement；普通 SELECT 返回原冻结类型。
- 快照：定义 query 编码、外层 Span 和开关行为，说明去重针对整个输出元组，前端本身不去重。
- 易错点：去重应作用于完整投影元组；不能在 AST 阶段删除重复列名来模拟 DISTINCT。
- 整合范围：本任务只交语法。完整 DISTINCT 还需另行定义 B 的去重计划和 D 的去重算子；现有 B-E02 冗余节点删除不能替代。

## 测试用例

1. `test_a_e03_distinct_projection`

   - 输入：SELECT DISTINCT name,age FROM t;
   - 必须断言：外层 feature=distinct；query 的列顺序 name、age；没有伪列 distinct。

2. `test_a_e03_distinct_star`

   - 输入：SELECT DISTINCT * FROM t;
   - 必须断言：query.columns=null，表名 t，payload 可 JSON 往返。

3. `test_a_e03_double_distinct`

   - 输入：SELECT DISTINCT DISTINCT id FROM t;
   - 必须断言：第二个 DISTINCT 处报语法错误，期望投影列或星号。

4. `test_a_e03_core_unchanged`

   - 输入：分别开关扩展解析 SELECT id FROM t;
   - 必须断言：都返回相同 SelectStmt 类型、字段和 Span，非扩展输入不被包装。
