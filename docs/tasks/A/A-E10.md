# A-E10 SQL Fuzz、变异与失败用例缩减

## 课程依据

C-S4、C-S37、C-S38、C-S41；G-P6、G-P7；D-S18

材料建议合法生成、非法变异与失败缩减；本任务给出可复现前端测试工具，不以随机运行次数替代断言。

## 任务目标

用固定随机种子生成有深度和长度上限的核心 SQL，附带预期语句种类或 AST 摘要；另做明确破坏文法的变异。记录种子、输入、失败分类和原异常；用确定性 delta debugging 删除片段，保持同一失败谓词时缩短用例。

## 输入输出

输入是 UTF-8 SQL 文本或冻结 Token 序列；输出是冻结 Token/AST、结构化诊断或版本化 `ExtensionStatement`。不得查询 Catalog、访问存储或执行 SQL。

## 公共接口

`FrontendPort.parse(source: str) -> list[Statement]`；核心产物只使用冻结的 Token、AST、Span 与错误类型，扩展产物使用 `ExtensionStatement(feature, version, payload, span)`。

扩展不得直接改变冻结 AST、Bound AST、Plan 或 Protocol；跨层扩展统一使用 `ExtensionStatement`、`BoundExtension`、`ExtensionPlan(feature, version, payload, span)`。

## 实现步骤

1. 先定义 Crash、Wrong Accept、Wrong Reject、位置错误等失败谓词。
2. 实现固定种子生成与受控变异，失败日志包含可重放命令。
3. 对人工注入的失败谓词演示缩减，确认工具本身可被验收。

## 预期代码结构解释

- generate_valid(seed,count)：按独立小文法生成 SQL 与预期摘要，不能用被测 Parser 的输出充当唯一真值。
- mutate_invalid：选择删除必需 FROM、截断引号等保证破坏文法的变异；仅改空白的变异属于等价合法输入。
- minimize(sql,predicate)：尝试删除块并保留同一失败类别，停止时给出不能再按当前粒度缩短的用例；不能把错误位置变化当原缺陷。
- 易错点：删字符未必让 SQL 非法；生成器必须知道该变异的预期，否则 Wrong Accept/Reject 统计没有意义。
- 整合范围：工具仅放测试目录，生产代码不得依赖；可向新 AI 隐藏测试会话提供生成规则，不提供原成员测试答案。

## 测试用例

1. `test_a_e10_reproducible`

   - 输入：seed=2026、count=200、最大表达式深度=4，运行两次
   - 必须断言：SQL 列表和摘要逐项相同；每条均解析成功且语句种类匹配生成预期。

2. `test_a_e10_invalid_mutation`

   - 输入：从 SELECT id FROM t; 删除必需 FROM；从 'abc' 删除闭引号
   - 必须断言：分别得到 SyntaxError、LexicalError，不能被标为合法用例。

3. `test_a_e10_minimizer`

   - 输入：人工谓词为输入含连续字符串 BAD，原文 xxBADyy
   - 必须断言：缩减结果恰为 BAD，谓词保持真；重复运行相同结果。

4. `test_a_e10_failure_record`

   - 输入：注入一次可控 Parser 内部异常
   - 必须断言：日志保存种子、完整 SQL、Crash 类别和异常类型；重放再次触发，不被吞成用户语法错误。
