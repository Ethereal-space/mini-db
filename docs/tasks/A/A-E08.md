# A-E08 Panic Mode 错误恢复

## 课程依据

C-S19、C-S22、C-S35、C-S38；G-P3；D-S18

材料把错误恢复列为进阶工程能力；核心 parse 保持首错停止，恢复通过独立入口开启。

## 任务目标

增加 parse_recovering(source) 的本地结果结构，分别保存成功 AST、诊断和原语句序号。语法失败后同步到下一分号或 EOF；当前错误语句整体丢弃。核心 FrontendPort.parse 不变，恢复产物不得默认送入执行器；词法未闭合字符串仍可停止后续恢复。

## 前置任务

本地依赖 A-B06 和各语句 Parser。 扩展输入以公共v1字段表为准，个人快照只验证同一格式。

前置缺失时，只能在本成员授权目录内补齐最小必要部分；跨成员能力使用冻结 Protocol 和 tests 中的 Fake。

## 输入输出

输入是 UTF-8 SQL 文本或冻结 Token 序列；输出是冻结 Token/AST、结构化诊断或版本化 `ExtensionStatement`。不得查询 Catalog、访问存储或执行 SQL。

## 公共接口

`FrontendPort.parse(source: str) -> list[Statement]`；核心产物只使用冻结的 Token、AST、Span 与错误类型，扩展产物使用 `ExtensionStatement(feature, version, payload, span)`。

扩展不得直接改变冻结 AST、Bound AST、Plan 或 Protocol；跨层扩展统一使用 `ExtensionStatement`、`BoundExtension`、`ExtensionPlan(feature, version, payload, span)`。

## 实现步骤

1. 定义恢复结果和不能安全恢复的词法错误策略。
2. 加入分号同步和进展断言，保留原核心入口。
3. 测试连续错误、尾部错误和内部异常暴露。

## 预期代码结构解释

- 恢复入口：在单语句边界捕获专用 SyntaxError，记录诊断，不捕获任意内部异常。
- synchronize：至少消费一个 Token，直到分号/EOF；同步分号也消费，保证不会反复报告同一位置。
- 结果结构：单独列出 errors 和 statements，对每项保存 statement_index；不得把失败语句伪造成空 AST。
- 易错点：恢复用于编辑器或诊断展示，不意味着出错脚本剩余语句已获准执行。
- 整合范围：可完全独立完成；若 D CLI 展示恢复结果，需额外显式诊断入口，不能改变冻结 execute 的核心执行语义。

## 测试用例

1. `test_a_e08_recover_next`

   - 输入：SELECT FROM t; SELECT id FROM t;
   - 必须断言：errors 一项；成功 AST 一项对应原第 2 句；第二句位置仍按原全文计数。

2. `test_a_e08_consecutive_errors`

   - 输入：SELECT; DELETE; SELECT * FROM t;
   - 必须断言：两条诊断和一条成功 AST，有限次循环终止，没有重复报告同一位置。

3. `test_a_e08_eof_error`

   - 输入：SELECT id FROM
   - 必须断言：一条 EOF 诊断、无成功 AST，恢复停止，不越界读取。

4. `test_a_e08_core_unchanged`

   - 输入：用核心 parse 解析第一项测试输入
   - 必须断言：仍在首句抛 SyntaxError；不返回第二句且不静默切换恢复模式。
