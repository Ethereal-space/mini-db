# A-E01 UPDATE 语法扩展

## 课程依据

G-P4；C-S6、C-S35；D-S17

UPDATE 为可选语法；本任务只完成前端扩展，不宣称数据库已具备行更新。

## 任务目标

解析 UPDATE t SET col=expr[,col=expr] [WHERE expr]，返回 feature=update、version=1 的 ExtensionStatement。payload 固定 table、assignments、where；每个赋值为 {column,expr}，表达式按 {kind,fields,span} 编码，禁止把 dataclass 塞进 JSON。

## 输入输出

输入是 UTF-8 SQL 文本或冻结 Token 序列；输出是冻结 Token/AST、结构化诊断或版本化 `ExtensionStatement`。不得查询 Catalog、访问存储或执行 SQL。

## 公共接口

`FrontendPort.parse(source: str) -> list[Statement]`；核心产物只使用冻结的 Token、AST、Span 与错误类型，扩展产物使用 `ExtensionStatement(feature, version, payload, span)`。

扩展不得直接改变冻结 AST、Bound AST、Plan 或 Protocol；跨层扩展统一使用 `ExtensionStatement`、`BoundExtension`、`ExtensionPlan(feature, version, payload, span)`。

## 实现步骤

1. 先写 payload 快照与四类 fixture。
2. 增加受开关控制的 UPDATE 入口，复用公共表达式与位置。
3. 回归四类核心 SQL，并记录扩展 AST 的逐字段解释。

## 预期代码结构解释

- parse_update：消费目标表和至少一项 SET，顺序保存赋值；重复目标列留给语义阶段。
- parse_assignment：列名后必须 =，右侧复用表达式入口；逗号结束当前赋值，不吞掉 WHERE。
- 扩展快照：记录 feature/version、payload 字段及示例；核心 AST 不增加字段，未启用扩展时明确拒绝 UPDATE。
- 易错点：语法接受重复赋值不等于执行合法；不要在 A 实现列更新或页迁移。
- 整合范围：独立完成只验 payload；完整 UPDATE 需要 B-E04、D-E02 与 C-E07 及一次扩展整合。

## 测试用例

1. `test_a_e01_update_payload`

   - 输入：UPDATE student SET age=21,name='李四' WHERE id=1;
   - 必须断言：feature=update；table=student；赋值列顺序 age、name；where 编码为 id=1；payload 可 JSON 往返。

2. `test_a_e01_update_all`

   - 输入：UPDATE t SET id=2;
   - 必须断言：where=null，assignments 恰一项，表达式值为 2。

3. `test_a_e01_missing_value`

   - 输入：UPDATE t SET id=;
   - 必须断言：在分号报缺操作数，Span 精确覆盖该分号。

4. `test_a_e01_disabled`

   - 输入：关闭扩展解析 UPDATE t SET id=2;
   - 必须断言：返回明确未启用语法错误；启用与关闭时核心 SELECT AST 相同。
