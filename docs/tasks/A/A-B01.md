# A-B01 Token、关键字、标识符与行列位置

## 课程依据

G-P3、G-P5；C-S8、C-S9、C-S10、C-S12；D-S2、D-S17

材料要求 Token 包含种别、词素和行列位置。本项目进一步固定 Unicode 码点、半开 Span、CRLF 和 Tab 规则，使四人共享同一错误定位口径。

## 任务目标

建立 Lexer 的字符游标、关键字表和标识符扫描。ASCII 标识符匹配 [A-Za-z_][A-Za-z0-9_]*；规范名小写，lexeme 原样保存。所有 Token 使用统一 Span，最后恰好一个 EOF。空白不产生 Token，但必须更新位置；非法字符报词法错误。此任务不通过字符串 split 实现，也不在 Lexer 查询 Catalog。 标识符最长64字符；超过时在完整词素span报IDENTIFIER_TOO_LONG。

## 实现步骤

1. 先用位置测试固定 Position 和 Span 的含义，再实现统一 advance。
2. 实现关键字识别、ASCII 标识符与 EOF，测试 token.kind、lexeme、value 三者差异。
3. 增加空输入、CRLF、Tab、Unicode 非法标识符测试，逐步追踪游标变化并写入讲解。

## 预期代码结构解释

- Lexer(source)：持有 source、offset、line、column；advance 只移动字符游标，遇 CRLF 一次换行，其他字符列数加一。所有扫描分支通过它更新位置，保持 offset 与 source 切片一致。
- scan_identifier()：从合法首字符消费到第一个非标识符字符，取原文为 lexeme，再查规范化关键字表决定 kind。name 与 NAME 的规范名相同，不能把 student_id 拆成关键字和尾部。
- tokenize()：依次跳过空白、扫描成分并追加 EOF；Span.start 为进入扫描前的位置，Span.end 为扫描后位置。未知字符抛 LexicalError，错误覆盖该字符且保留阶段和原因。
- 易错点：不要用字节长度计算中文位置，也不要先统一换行再扫描，否则 offset 不再对应用户原文。
- 整合范围：只以 contracts 构造断言，不需要 Fake Catalog 或存储；向 B 交付的名称必须已经规范化，词素和位置仍可追溯原文。

## 测试用例

1. `test_a_b01_keyword_identifier`

   - 输入：SeLeCt name FROM Student
   - 必须断言：种别依次 SELECT、IDENTIFIER、FROM、IDENTIFIER、EOF；lexeme 保留 SeLeCt 和 Student；标识符 value 为 name、student。

2. `test_a_b01_positions`

   - 输入：SELECT
	name
   - 必须断言：name 的 start=(offset=9,line=2,column=2)，end=(13,2,6)；EOF 位于 (13,2,6)。

3. `test_a_b01_empty`

   - 输入：空字符串与三个空格
   - 必须断言：均只有一个 EOF；位置分别为 (0,1,1)、(3,1,4)，没有空 AST 占位。

4. `test_a_b01_identifier_boundary`

   - 输入：select_x _a A1
   - 必须断言：全部为 IDENTIFIER；规范值为 select_x、_a、a1；不把 select_x 误判为 SELECT。

5. `test_a_b01_illegal_character`

   - 输入：SELECT @
   - 必须断言：LexicalError 的 start=(7,1,8)，end=(8,1,9)，阶段 LEXICAL，原因明确包含非法字符 @。

6. `test_a_b01_identifier_limit`

   - 输入：64个a与65个a作为标识符。
   - 必须断言：前者合法，后者LEXICAL错误覆盖完整标识符，不截断。

## 理解考试与小修改

- 讲解题：随机讲解 advance：为什么 CRLF 的 offset 增加 2，line 只增加 1？
- 答案要点：offset 索引原字符串中的两个码点；CRLF 表示一个逻辑换行；下一字符的 column 重置为 1。
- 现场小修改：把 Tab 计列改为跳到下一个 4 列制表位，在练习副本修改位置测试并说明这是契约变更；核心实现恢复原约定。
