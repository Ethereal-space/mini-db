# A-B06 多语句、诊断、Token 与 AST 输出

## 课程依据

G-P3、G-P6、G-P7；C-S8、C-S20、C-S22、C-S37、C-S40、C-S42；D-S17、D-S18

材料要求文件或标准输入多语句、中间结果输出、期望符号诊断及边界测试。本任务形成可独立交付的 FrontendPort，不承担 CLI 和执行职责。

## 任务目标

实现 FrontendPort.parse(source)→语句列表及稳定 Token、AST 文本/数据格式。分号分隔语句，最后一条允许省略分号；允许空语句；核心遇第一处错误停止并不返回半成功列表。输出含节点类型和关键字段，不含内存地址。提供只读诊断回调供整合层收集中间结果，未设置回调时行为不变。

## 输入输出

输入是 UTF-8 SQL 文本或冻结 Token 序列；输出是冻结 Token/AST、结构化诊断或版本化 `ExtensionStatement`。不得查询 Catalog、访问存储或执行 SQL。

## 公共接口

`FrontendPort.parse(source: str) -> list[Statement]`；核心产物只使用冻结的 Token、AST、Span 与错误类型，扩展产物使用 `ExtensionStatement(feature, version, payload, span)`。

扩展不得直接改变冻结 AST、Bound AST、Plan 或 Protocol；跨层扩展统一使用 `ExtensionStatement`、`BoundExtension`、`ExtensionPlan(feature, version, payload, span)`。

## 实现步骤

1. 实现分号/EOF 驱动的多语句循环，覆盖空输入与连续分号。
2. 集中 SyntaxError 构造，统一实际 Token、期望集合、原因和 Span；EOF 也有有效位置。
3. 输出 Token 与 AST 的稳定表示，用快照加关键字段断言验证，生成真实调用链讲解。

## 预期代码结构解释

- parse(source)：先 tokenize，再循环跳过空分号、解析单语句、检查分号或 EOF；每轮必须前进。整个前端无磁盘修改，多语句中的语义可执行顺序由整合层处理。
- format_tokens()/format_ast()：接收已生成对象，产生确定性文本；字段次序固定，包含 Span 和规范值，字符串用明确转义，不调用 Parser 重新解析。
- ast_to_data() 与诊断回调：递归转成 {kind,fields,span} 的 JSON 基本值映射；可选回调只观察 Token/AST，异常诊断保持原类型和位置，不篡改产物。
- 易错点：核心错误停止与 A-E08 的恢复模式必须有明确开关；不能静默吞掉错误后声称所有 SQL 已成功解析。
- 整合范围：独立测试只跑 frontend 与 contracts；诊断回调用本地列表 Fake，不导入 integration 或 D 的 CLI。整合层把 Token/AST 回调拼到 Trace。

## 测试用例

1. `test_a_b06_multiple_statements`

   - 输入：;CREATE TABLE t(id INT);;INSERT INTO t VALUES(1);SELECT * FROM t
   - 必须断言：按顺序返回 CreateTableStmt、InsertStmt、SelectStmt 三项；末尾无分号合法，空语句不产生节点。

2. `test_a_b06_comment_only`

   - 输入：-- only
/* comment */ ; ;
   - 必须断言：parse 返回 []；Lexer 恰有分号和 EOF，不产生假语句，循环终止。

3. `test_a_b06_missing_statement_separator`

   - 输入：SELECT * FROM t SELECT * FROM t;
   - 必须断言：在第二个 SELECT 的第 1 行第 17 列报错，期望分号或 EOF；不把两句自动拼接。

4. `test_a_b06_stable_formatter`

   - 输入：同一 SELECT id FROM t WHERE id=1; 连续解析并格式化两次
   - 必须断言：两次文本逐字符相同；数据表示包含 SelectStmt、BinaryExpr、id、1 和各 Span；JSON 可往返且不含对象 repr 地址。

5. `test_a_b06_error_and_trace`

   - 输入：使用收集列表的诊断回调解析 SELECT id FROM;，另以无回调解析同文
   - 必须断言：两次均在分号第 1 行第 15 列报期望表标识符；回调可记录 Tokens，不能报告成功 AST；没有回调时错误字段一致。

## 理解考试与小修改

- 讲解题：为什么先 parse 整个脚本不会提前知道第二句所引用的表，而整合层仍可按顺序建表再插入？
- 答案要点：AST 只描述语法；整合层逐句 compile/execute，前一句执行更新 Catalog 后，后一句才语义绑定。
- 现场小修改：给 AST 格式化器增加可选隐藏 Span 的展示参数，验证默认输出完全不变，且核心 AST 仍保存所有位置。
