# A-E06 FLOAT、NULL、BOOL 和更多字面量

## 课程依据

C-S6、C-S9、C-S27、C-S35；D-S5、D-S17

更多类型与 NULL 是材料扩展；FLOAT Token 的核心识别不等于 FLOAT 列和三值逻辑已实现。

## 任务目标

在独立扩展开关下接受 FLOAT、BOOL 列类型及 TRUE、FALSE、NULL 字面量。新类型相关语句统一 types v1 包装，payload={statement}，内层为 JSON AST，类型名使用字符串；不能修改核心 DataType 枚举假装全链路兼容。

扩展不得直接改变冻结 AST、Bound AST、Plan 或 Protocol；跨层扩展统一使用 `ExtensionStatement`、`BoundExtension`、`ExtensionPlan(feature, version, payload, span)`。

## 预期代码结构解释

- scan_extended_keyword：新增受能力开关约束的类型/字面量关键字，保持字符串原值不被关键字替换。
- parse_extended_literal：TRUE/FALSE 为布尔，NULL 为 null，FLOAT 为数值；节点保留原 Span 和字面种类。
- types 包装：扩展 CREATE 和 INSERT 的字段编码明确区分 int 与 bool，核心模式继续拒绝新列类型。
- 易错点：Python bool 是 int 子类，JSON 编码和类型标记必须先区分 bool，避免三值逻辑前提被破坏。
- 整合范围：完整类型扩展需要 B-E08、D 求值扩展与 C 编码版本升级，共同建立独立基线后才合入。

1. `test_a_e06_types_create`

   - 输入：CREATE TABLE t(x FLOAT,ok BOOL);
   - 必须断言：扩展开启时 types.statement 为 CreateTableStmt 编码，列类型分别 FLOAT、BOOL；核心关闭时拒绝。

2. `test_a_e06_literal_values`

   - 输入：INSERT INTO t VALUES(3.14,TRUE,NULL);
   - 必须断言：扩展字面值分别为 3.14、true、null，BOOL 不编码成整数 1。

3. `test_a_e06_string_unchanged`

   - 输入：INSERT INTO t VALUES('NULL','true');
   - 必须断言：两个值仍为字符串 NULL、true，不被替换成空值或布尔值。

4. `test_a_e06_unknown_type`

   - 输入：CREATE TABLE t(x MONEY);
   - 必须断言：在 MONEY 报不支持类型，错误列和词素准确，不能自动猜成 FLOAT。

## 理解考试与小修改

- 讲解题：为什么 x=NULL 不能直接按 Python 的 x==None 执行？
- 答案要点：SQL NULL 需要独立的未知真值和 IS NULL 规则；前端识别字面量并没有实现这种语义。
- 现场小修改：增加 FALSE 与 false 的等价 Token 测试，同时证明 'FALSE' 仍为字符串。
