# C-E06 顺序扫描预取

## 课程依据

G-P4、G-P8；C-S35；D-S8、D-S15

顺序访问与缓冲池原理的性能扩展，课程没有要求线程或异步I/O。

## 任务目标

扫描当前页完成复制并unpin后，尝试把next页提前装入缓存。预取是可失败的性能提示，不能抢占pin页或改变行顺序；容量1时可关闭预取。分别统计需求读与预取读，避免把预取计为普通命中来夸大收益。

## 前置任务

C-B05、C-B06；首先采用同步单页预取。 扩展输入以公共v1字段表为准，个人快照只验证同一格式。

前置缺失时，只能在本成员授权目录内补齐最小必要部分；跨成员能力使用冻结 Protocol 和 tests 中的 Fake。

## 输入输出

输入是冻结 TableMeta、RID、行值、页号和临时数据库文件；输出是可重启恢复的页数据、StoredRow、缓存统计或结构化存储错误。不得解析 SQL 或绑定列名。

## 公共接口

`StoragePort` 与 `CatalogRepositoryPort`；核心页大小固定为 4096 字节，行地址使用 `RID`，扫描返回 `Iterator[StoredRow]`，缓存观测使用 `BufferStats`。

扩展不得直接改变冻结 AST、Bound AST、Plan 或 Protocol；跨层扩展统一使用 `ExtensionStatement`、`BoundExtension`、`ExtensionPlan(feature, version, payload, span)`。

## 实现步骤

1. 加入可关闭开关，默认保持核心行为。
2. 实现有限单页预取和独立统计。
3. 对比开关两种扫描的值与RID。

## 预期代码结构解释

- prefetch(page_id)：已缓存则无重复I/O；只在有可用帧时装入，结束pin=0。
- scan_hook：读到可信next后触发，页链仍由原scan验证，不假定页号连续。
- metrics：记录prefetch_reads/useful/unused，结果正确性不得依赖预取成功。
- 易错点：同步预取未必更快；必须报告读取次数与测量条件，不能凭名称断言提升。
- 整合范围：独立存储优化；不要求其他成员同步，最终性能演示与D-E09可选组合。

## 测试用例

1. `test_prefetch_same_rows`

   - 输入：页链2→7→4，同数据分别开关预取。
   - 必须断言：结果顺序、值、RID完全相同。

2. `test_no_duplicate_read`

   - 输入：next页已缓存。
   - 必须断言：预取不再调用read_page。

3. `test_pinned_pool_skips_hint`

   - 输入：所有帧被其他访问pin。
   - 必须断言：预取跳过，无BufferFullError传播至用户查询。

4. `test_early_stop_no_pin_leak`

   - 输入：扫描取一行后停止。
   - 必须断言：预取帧和扫描帧pin均0，统计可区分未使用预取。
