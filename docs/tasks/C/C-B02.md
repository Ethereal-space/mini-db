# C-B02 页分配、释放、读写与空闲链表

## 课程依据

G-P4、G-P5、G-P7、G-P8；C-S2；D-S6、D-S7、D-S17

页分配、释放、固定长度读写来自指导书；空闲页链、页号复用及缓存失效顺序是项目实现方案。

## 任务目标

实现按页号定位的I/O：offset=page_id×4096。优先从空闲链头取页，无空闲页时追加。释放后的页用FREE头记录后继，page0与Catalog首页page1不可释放。所有读写严格校验页号和4096字节长度，允许复用已释放页但不允许通过旧缓存恢复其原数据。

## 实现步骤

1. 封装固定页I/O与合法页号检查，测试真实文件偏移。
2. 实现FREE页格式：magic=FREE，原页头next_page_id字段承载next_free，其余无效数据清零。
3. 实现分配/释放状态转换，并为缓存协调预留内部接口，禁止业务层绕过协调器释放页。

## 预期代码结构解释

- DiskManager.read_page/write_page：接收非负且小于page_count的页号；write严格接收4096字节。seek到页边界后读取或写入，短读短写转换为带page_id与offset的StorageIOError，未知编程错误继续暴露。
- allocate_page：free_head非-1时读取FREE页的next字段并前移链头，否则使用旧page_count并递增。返回页号时将页重置为零/指定新页头，不携带前一任记录；Superblock随分配状态一起写回。
- free_page与协调器：拒绝0、1、越界及重复释放。接入缓存后先确认pin_count=0，失效对应帧，再写FREE页头和更新free_head；旧dirty内容不得在释放后写回。释放不缩短文件。
- 释放分两层：表堆/存储协调器先确认页空且已从所有表链脱离，再令BufferPool失效帧，最后调用DiskManager释放。低层调用者必须满足此前提；活页或仍链接页释放拒绝。有效page_id<=2147483647，计数可存next上界；耗尽在分配前拒绝。
- 易错点：free_page若只修改空闲链而不清除缓存，旧dirty帧会在页重用后覆盖新记录，这是需要单独断言的错误。
- 整合范围：纯磁盘阶段使用本地Fake协调器；接入C-B05后必须再跑真实缓存失效测试。上层只通过C自己的统一存储服务释放页。

## 测试用例

1. `test_allocate_read_write_offsets`

   - 输入：新库连续分配两页，把4096字节A和B分别写入。
   - 必须断言：页号为2、3；文件长度16384；偏移8192和12288读到各自内容；page_count=4。

2. `test_free_list_lifo_reuse`

   - 输入：分配2、3、4后依次释放2、4，再分配两次。
   - 必须断言：返回4、2；page_count仍5；free_head最终-1；重用页无旧payload。

3. `test_invalid_page_and_length`

   - 输入：访问-1、page_count，写4095或4097字节；释放0、1。
   - 必须断言：均抛明确参数/存储错误；文件长度与Superblock保持不变。

4. `test_duplicate_free_rejected`

   - 输入：释放页2两次，再关闭、重开。
   - 必须断言：第二次失败且不形成自环；重开首次分配只返回一次2，再分配新页3。

5. `test_free_cache_coordination_contract`

   - 输入：用测试协调Fake模拟页2被pin，及未pin但dirty两种状态。
   - 必须断言：pin时拒绝释放且链头不变；dirty未pin时先invalidate后写FREE；后续flush不得写回旧payload。

6. `test_reject_live_or_linked_page_free`

   - 输入：分别释放有行页、空但仍在表链页。
   - 必须断言：协调器拒绝；文件字节、表链和缓存内容不变。

## 理解考试与小修改

- 讲解题：释放操作为什么不能只把页号放进一个Python列表？为什么重复释放可能造成链表环？
- 答案要点：重启需要从文件恢复空闲页；重复链接同一页会破坏单一所有权和后继关系，可能循环分配同一页。
- 现场小修改：增加检查空闲链是否存在环的只读方法；人工构造2→3→2，断言有限步骤内报告损坏。
