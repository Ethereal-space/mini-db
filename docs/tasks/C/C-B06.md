## 预期代码结构解释

- TableHeap：create_table先检验ID与columns，再分配空页并推进next_table_id；insert先encode，逐页找空间，页满新建并连接。scan校验table_id与页链无环，复制一页存活行后unpin，再yield StoredRow；RID保留原槽。
- PageCatalogRepository：内置schema=(table_id INT,table_name VARCHAR,first_page_id INT,column_ordinal INT,column_name VARCHAR,column_type VARCHAR)。save_table写各列，load_tables按table_id分组并检查ordinal连续、字段一致、名称唯一，恢复不可变TableMeta。
- 删除与错误：mark_delete先验证RID页属于该表，再标记原Slot，避免跨表删除。数据损坏附RID/page_id，写回失败向上传递；不承诺I/O中途失败时的跨页事务回滚。next_table_id作为只读初值交给装配层。
- 易错点：yield放在持有pin的with内部会让调用方暂停扫描时占住页面；Catalog加载不可依赖尚未初始化的CatalogService。
- 整合范围：通过本地TableMeta直接验收，不等待A/B/D。整合时B注入Repository，D注入StoragePort，成功CREATE按分配ID→建页→登记→flush顺序执行。

## 测试用例

1. `test_thousand_rows_cross_pages`

   - 输入：schema=(INT,VARCHAR)，插入1000行(i,'x'×160)，缓存容量2。
   - 必须断言：每行166字节、每槽8字节，每页23行，共44个数据页；scan得到1000个唯一RID及原值，pin最终为0。

2. `test_delete_and_restart`

   - 输入：保存表与3行，删除中间行，flush、关闭全部实例并重开。
   - 必须断言：Catalog恢复相同schema与first_page_id；scan只返回两行；原删除槽仍有tombstone。

3. `test_catalog_uses_pages`

   - 输入：建立足够多含长列名的表使Catalog超过一页，并保存。
   - 必须断言：Catalog页链长度≥2；文件中可通过RowCodec逐条读回六字段；无json、pickle或旁路元数据文件。

4. `test_scan_early_stop_unpins`

   - 输入：扫描多页表只next一次后保留迭代器，再请求其他页。
   - 必须断言：首次yield前所有页已unpin；容量1仍可装入其他页；关闭迭代器无泄漏。

5. `test_reject_wrong_rid_and_catalog_corruption`

   - 输入：用表B的RID删除表A记录；另构造Catalog列序号0、2。
   - 必须断言：跨表操作失败且两表数据不变；目录加载因ordinal不连续报StorageFormatError，不能返回残缺schema。

6. `test_oversize_row_before_allocation`

   - 输入：合法schema包含1015个INT，新行编码4060字节。
   - 必须断言：RowTooLargeError；分配次数0、page_count、页链与文件字节不变。
