# C-E04 页面校验和与损坏检测

## 课程依据

G-P6、G-P8；C-S37；D-S6、D-S13

课程要求I/O异常与边界测试；校验和属于加强完整性检测的扩展。

## 任务目标

采用CRC32检测页字节被意外修改。v2文件为每页保留最后4字节校验值，计算时该区清零；数据页payload终点改为4092。v1保持原格式，只读检查不偷偷升级；显式迁移另立任务。 页构造按版本选择payload终点：v1=4096，v2=4092；旧版读写回归单独验证。

## 前置任务

C-B01、C-B02、C-B05；独立存储格式v2基线。 扩展输入以公共v1字段表为准，个人快照只验证同一格式。

前置缺失时，只能在本成员授权目录内补齐最小必要部分；跨成员能力使用冻结 Protocol 和 tests 中的 Fake。

## 输入输出

输入是冻结 TableMeta、RID、行值、页号和临时数据库文件；输出是可重启恢复的页数据、StoredRow、缓存统计或结构化存储错误。不得解析 SQL 或绑定列名。

## 公共接口

`StoragePort` 与 `CatalogRepositoryPort`；核心页大小固定为 4096 字节，行地址使用 `RID`，扫描返回 `Iterator[StoredRow]`，缓存观测使用 `BufferStats`。

扩展不得直接改变冻结 AST、Bound AST、Plan 或 Protocol；跨层扩展统一使用 `ExtensionStatement`、`BoundExtension`、`ExtensionPlan(feature, version, payload, span)`。

## 实现步骤

1. 冻结v2格式快照及测试样例。
2. 接入页I/O，更新v2容量计算。
3. 翻转头部和payload字节验证损坏路径。

## 预期代码结构解释

- crc_page：复制页并清零校验区，对4096字节求CRC32，存uint32 little-endian。
- verify_before_decode：磁盘读取后先验证再解释Slot；失败报告page_id与期望/实际CRC。
- version_gate：v2新建库使用4092终点；v1读写走原路径，不允许混合头字段。
- 易错点：CRC只能检测损坏，不提供恢复、加密或事务原子性。
- 整合范围：C独立验收v2库；只有小组选中格式升级后进入扩展整合，不覆盖核心v1演示库。

1. `test_v2_crc_roundtrip`

   - 输入：写入v2数据页并重开。
   - 必须断言：CRC验证通过、数据往返一致。

2. `test_detect_bit_flip`

   - 输入：分别翻转头部及payload一位。
   - 必须断言：均ChecksumError且附页号，不能返回行。

3. `test_v2_exact_capacity`

   - 输入：空v2页插入4052字节。

   - 输入：打开核心v1文件后关闭。
   - 必须断言：文件哈希及version不变，仍可由核心读取。
