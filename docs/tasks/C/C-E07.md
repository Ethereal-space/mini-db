## 输入输出

输入是冻结 TableMeta、RID、行值、页号和临时数据库文件；输出是可重启恢复的页数据、StoredRow、缓存统计或结构化存储错误。不得解析 SQL 或绑定列名。

## 公共接口

`StoragePort` 与 `CatalogRepositoryPort`；核心页大小固定为 4096 字节，行地址使用 `RID`，扫描返回 `Iterator[StoredRow]`，缓存观测使用 `BufferStats`。

扩展不得直接改变冻结 AST、Bound AST、Plan 或 Protocol；跨层扩展统一使用 `ExtensionStatement`、`BoundExtension`、`ExtensionPlan(feature, version, payload, span)`。

## 实现步骤

1. 写扩展契约规定返回RID和失败语义。
2. 分别实现缩短与迁移分支。
3. 断言正常完成后只扫描到一个新值。

## 预期代码结构解释

- preflight：验证RID属于表、行未删除以及新值完整可编码，失败不动旧行。
- in_place：保留slot_id、更新length，剩余字节清零；不擅自增大连续空闲区。
- relocate：先成功insert得到new_rid，再tombstone旧槽；插入失败保留旧行，I/O中途失败按非事务边界报告。
- 易错点：先删旧行再插新行会在空间不足时丢数据；返回新RID的契约必须告知索引使用者。

## 测试用例

1. `test_short_update_same_rid`

   - 输入：'abcdef'更新为'xy'。
   - 必须断言：返回原RID，读出xy，无旧尾内容。

2. `test_long_update_new_rid`

   - 输入：满页短串更新为200字节串。
   - 必须断言：返回不同RID；旧槽删除；scan只含新行一次。

3. `test_failed_insert_keeps_old`

   - 输入：迁移insert注入分配失败。
   - 必须断言：旧槽未删除且旧值仍可读。

4. `test_reopen_updated_row`

   - 输入：成功更新后flush并重开。
   - 必须断言：新值存在，旧值不再返回。
