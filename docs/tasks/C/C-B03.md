# C-B03 4096 字节 Slotted Page、Slot 与 tombstone

## 课程依据

G-P4、G-P5、G-P8；C-S43；D-S6、D-S8、D-S15

指导书要求行页映射与删除；D-S6给出页头、记录和槽概念。32字节页头、8字节Slot及双端增长为项目冻结格式。

## 任务目标

用bytearray管理一个精确4096字节页，支持插入、按槽读出、遍历存活槽和逻辑删除。记录不能跨页；空间不足必须在修改前失败。基础版tombstone不回收空间，不减少slot_count，也不改变其他槽号，确保先前获得的RID持续定位同一个槽。

## 实现步骤

3. 实现validate检测坏槽及页头交叉，并将存活遍历作为表堆的唯一槽入口。

## 预期代码结构解释

- Page.header：使用<4sIiHHHHIII，偏移0/4/8/12/14/16/18/20/24/28依次存magic、page_id、next、slot_count、free_start、free_end、flags、table_id、version、reserved；初值free_start=32、free_end=4096。
- insert(payload)->slot_id：需要len(payload)+8字节；新槽位于32+slot_id×8，记录起点为旧free_end-len(payload)。更新slot_count、free_start及free_end；成功后free_start=32+8×slot_count且不大于free_end。
- read/mark_deleted/iter_live：Slot格式<HHHH；bit0是删除位，reserved为0。删除只改flags，重复删除返回False；读已删除槽报RecordDeletedError。解码先校验槽边界、记录范围和非重叠，不信任文件字段。
- 易错点：容量计算必须包含新Slot的8字节；字符串的字符数与实际payload字节数不是一回事。
- 整合范围：只依赖标准库与自身常量，使用人工payload独测；C-B04负责解释行内容，本任务不读取SQL类型。

## 测试用例

1. `test_exact_fit_page`

   - 输入：空页插入4056字节payload，再尝试插入1字节。
   - 必须断言：首槽0、offset=40、length=4056、free_start=free_end=40；第二次PageFullError，页字节不变。

2. `test_two_sided_growth`

   - 输入：依次插入4000字节A和48字节B。
   - 必须断言：槽0 offset=96，槽1 offset=48；slot_count=2、free_start=48、free_end=48；两条读出完全一致。

3. `test_tombstone_preserves_rid`

   - 输入：插入a、bb、ccc后删除槽1两次。
   - 必须断言：首次True、再次False；槽数仍3；存活槽号[0,2]；槽2数据未移动；读取槽1报RecordDeletedError。

4. `test_serialize_roundtrip`

   - 输入：页号9、table_id=3、next=12，含中文编码payload和删除槽。
   - 必须断言：序列化长度4096；重新解析后头字段、槽flags及存活payload逐字节相同。

5. `test_reject_corrupt_slot`

   - 输入：分别构造free_start>free_end、payload越界、槽区与记录区重叠、非法槽号。
   - 必须断言：前三项StorageFormatError且附page_id；非法槽号报SlotNotFoundError；不能返回截断的假记录。
