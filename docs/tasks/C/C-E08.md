# C-E08 Overflow Page 大记录

## 课程依据

G-P4、G-P8；C-S35；D-S6、D-S7、D-S15

课程讨论页与行组织；超页记录是可选存储扩展，核心VARCHAR上限保持255字节。

## 任务目标

先提供字节对象层的write_blob/read_blob/delete_blob，主记录保存总长度、首溢出页和版本。溢出链使用专用页类型，验证长度与环；独立验收可用10000字节payload，不把SQL VARCHAR悄悄扩到新范围。

## 输入输出

输入是冻结 TableMeta、RID、行值、页号和临时数据库文件；输出是可重启恢复的页数据、StoredRow、缓存统计或结构化存储错误。不得解析 SQL 或绑定列名。

## 公共接口

`StoragePort` 与 `CatalogRepositoryPort`；核心页大小固定为 4096 字节，行地址使用 `RID`，扫描返回 `Iterator[StoredRow]`，缓存观测使用 `BufferStats`。

扩展不得直接改变冻结 AST、Bound AST、Plan 或 Protocol；跨层扩展统一使用 `ExtensionStatement`、`BoundExtension`、`ExtensionPlan(feature, version, payload, span)`。

## 实现步骤

1. 冻结描述符与专用页布局。
2. 实现跨页读取和严格结构验证。
3. 验证删除重用及分配失败清理。

## 预期代码结构解释

- write_blob：按冻结v2块容量切片，链接专用页，返回描述符；失败列出已分配页供清理。
- read_blob：逐页复制后unpin，校验类型、next、累计长度及最多页数，拒绝截断/环。
- delete_blob：先验证整链，再经缓存失效协调逐页释放；不能释放其他表数据页。
- 易错点：单独大字节对象成功不代表SQL大字符串已经可用；类型、行格式与语义上限需共同升级。
- 整合范围：C独立字节层完成；完整SQL大字段需A-E06、B-E08及相应执行/codec格式整合，未选中不合核心。
