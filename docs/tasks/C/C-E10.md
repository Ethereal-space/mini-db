# C-E10 WAL 页面日志与恢复基础

## 课程依据

G-P6；C-S35；D-S8、D-S13、D-S17

Redo/Undo与事务为PPT背景和长期扩展，本卡只实现单写入者的页级redo恢复模型。

## 任务目标

把一组页后镜像作为提交单元写入WAL，含长度、序号、页号、校验和与COMMIT记录。先持久化完整提交日志，再写数据页；恢复只重放完整已提交单元。明确不含多事务并发、undo或SQL级隔离。

## 实现步骤

1. 写日志格式及故障点表。
2. 实现单批次日志先行写回。
3. 用子进程故障注入验证恢复，不只模拟正常退出。

## 预期代码结构解释

- append_batch：完整页镜像带单调序号；COMMIT含批次校验，调用flush与os.fsync后才允许数据页写回。
- recover：顺序验证日志，尾部不完整批次忽略，完整提交按序覆盖页；重放后fsync数据文件。
- idempotence：相同日志重复重放得到相同页字节；恢复成功后才截断/归档日志。
- 提交门控：未提交页镜像保存在批次私有映射，不进入可淘汰dirty帧；WAL镜像和COMMIT fsync成功后才安装到BufferPool/写数据页。所有数据页（含Superblock和Catalog）统一遵守。
- 易错点：Python文件flush不等于fsync；页日志成功也不等于SQL事务语义完整。
- 整合范围：C独立故障模型可验收；与D-E07组合前还需定义SQL提交边界和回滚策略，不能仅靠命令外壳宣布事务完成。

## 测试用例

1. `test_committed_redo_after_crash`

   - 输入：COMMIT已fsync，数据页尚未写时结束进程。
   - 必须断言：重开恢复出全部批次新页。

2. `test_ignore_uncommitted_tail`

   - 输入：只有页镜像，无完整COMMIT。
   - 必须断言：恢复不应用该批次。

3. `test_redo_idempotent`

   - 输入：同日志恢复两次。
   - 必须断言：数据文件哈希相同。

4. `test_corrupt_log_detection`

   - 输入：修改完整日志中部一字节。
   - 必须断言：校验失败并停止，不能静默重放损坏页。

5. `test_uncommitted_pages_never_evict_to_data`

   - 输入：Buffer容量1；未提交修改2页迫使缓存替换，再结束进程。
   - 必须断言：数据文件保持旧字节；未提交镜像未进入可写回缓存，恢复不应用。
