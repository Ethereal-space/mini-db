# C-E03 Free Space Map

## 课程依据

G-P4、G-P8；C-S35；D-S6、D-S7、D-S15

材料涉及页空闲空间；建立候选页索引是可选性能扩展。

## 任务目标

用每表page_id到可插入字节上界的索引减少INSERT遍历。Map只是提示，目标页必须重新核实；缺失或过期时回退正确页扫描。首次打开可扫描页链重建，不引入旁路权威元数据文件。

## 前置任务

本地C-B06；基础版先使用可重建的内存Map。 扩展输入以公共v1字段表为准，个人快照只验证同一格式。

前置缺失时，只能在本成员授权目录内补齐最小必要部分；跨成员能力使用冻结 Protocol 和 tests 中的 Fake。

## 输入输出

输入是冻结 TableMeta、RID、行值、页号和临时数据库文件；输出是可重启恢复的页数据、StoredRow、缓存统计或结构化存储错误。不得解析 SQL 或绑定列名。

## 公共接口

`StoragePort` 与 `CatalogRepositoryPort`；核心页大小固定为 4096 字节，行地址使用 `RID`，扫描返回 `Iterator[StoredRow]`，缓存观测使用 `BufferStats`。

扩展不得直接改变冻结 AST、Bound AST、Plan 或 Protocol；跨层扩展统一使用 `ExtensionStatement`、`BoundExtension`、`ExtensionPlan(feature, version, payload, span)`。

## 实现步骤

1. 实现Map纯结构和候选排序。
2. 把更新接入插入成功分支。
3. 注入错误估计验证回退与重建。

## 预期代码结构解释

- FreeSpaceMap.find(size)：按确定顺序返回估计容量足够的候选，计算含新Slot开销。
- refresh(page)：插入、删除空间复用、压缩后更新提示；无复用的tombstone不增加可用容量。
- fallback：候选失败先刷新再尝试下一页，最终按原表堆逻辑分配，避免无限重试。
- 易错点：把提示当作权威容量会在压缩或删除后产生错误；优化不能改变正确性。
- 整合范围：仅C内部扩展；不改变StoragePort，性能对照用同样数据与缓存容量。
