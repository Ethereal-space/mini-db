# C-E01 删除空间复用

## 课程依据

G-P4、G-P8；C-S35；D-S6、D-S15

删除与空间管理的拓展；复用策略及旧RID约束属于项目扩展选择。

## 任务目标

在不重用槽号的前提下复用已删除payload空洞：新记录始终获得新Slot，旧RID持续保持删除状态。采用first-fit找足够空洞，仍为新Slot预留8字节。核心文件可读，避免引入需要跨成员修改的RID代数。

## 输入输出

输入是冻结 TableMeta、RID、行值、页号和临时数据库文件；输出是可重启恢复的页数据、StoredRow、缓存统计或结构化存储错误。不得解析 SQL 或绑定列名。

## 公共接口

`StoragePort` 与 `CatalogRepositoryPort`；核心页大小固定为 4096 字节，行地址使用 `RID`，扫描返回 `Iterator[StoredRow]`，缓存观测使用 `BufferStats`。

扩展不得直接改变冻结 AST、Bound AST、Plan 或 Protocol；跨层扩展统一使用 `ExtensionStatement`、`BoundExtension`、`ExtensionPlan(feature, version, payload, span)`。

## 实现步骤

1. 构造有洞但连续空间不足的页。
2. 加入洞搜索及新槽容量检查。
3. 验证旧RID和重启后的状态。

## 预期代码结构解释

- find_hole(size)：从删除槽收集空区，排序并合并相邻区；排除活记录与未来槽目录所占字节。
- insert_reusing_hole：先计算新目录边界，再选洞；成功才一次更新槽与记录，失败不改页。
- validate：存活payload不得重叠；已删除槽不是新记录地址，新旧RID不能别名。
- 易错点：复用已删除槽号会使旧RID指向新行；本任务明确只复用payload区。
- 整合范围：纯存储扩展可独立完成；无需A/B/D，集中合入后复跑核心RID删除测试。

## 测试用例

1. `test_reuse_payload_not_slot`

   - 输入：删除300字节槽1，再插入200字节。
   - 必须断言：新slot_id大于所有旧槽；新payload位于旧洞内；读取旧RID仍报删除。

2. `test_hole_too_small`

   - 输入：只有100字节洞，请求101字节且尾部不足。
   - 必须断言：PageFullError且字节不变。

3. `test_slot_directory_space_required`

   - 输入：payload有洞但目录无法再增长8字节。
   - 必须断言：拒绝插入，不覆盖现有记录。

4. `test_reopen_reuse_consistent`

   - 输入：复用后写回重开。
   - 必须断言：全部存活值与RID保持，删除槽未复活。
