# C-E02 页面压缩与 RID 保持

## 课程依据

G-P8；C-S35；D-S6、D-S15

页内空间回收的可选工程改进，不属于基础tombstone要求。

## 任务目标

把存活payload紧凑排列到页尾，只更新原Slot.offset。槽号与slot_count不变，删除槽继续带标记，长度可归零。使用临时页构造后替换，避免原地移动覆盖尚未复制的数据。

## 输入输出

输入是冻结 TableMeta、RID、行值、页号和临时数据库文件；输出是可重启恢复的页数据、StoredRow、缓存统计或结构化存储错误。不得解析 SQL 或绑定列名。

## 公共接口

`StoragePort` 与 `CatalogRepositoryPort`；核心页大小固定为 4096 字节，行地址使用 `RID`，扫描返回 `Iterator[StoredRow]`，缓存观测使用 `BufferStats`。

扩展不得直接改变冻结 AST、Bound AST、Plan 或 Protocol；跨层扩展统一使用 `ExtensionStatement`、`BoundExtension`、`ExtensionPlan(feature, version, payload, span)`。

## 实现步骤

1. 做交错删除样例并记录所有RID。
2. 实现临时缓冲压缩和幂等性。
3. 通过写回重开及后续插入检查。

## 预期代码结构解释

- compact：先验证页，再复制存活payload到临时4096字节缓冲；依槽号保持映射。
- rewrite_slots：保留存活槽号/flags，重写offset；删除槽length=0，不能视为新槽。
- free_end：由存活payload总长度计算；free_start仍为32+8×slot_count，目录空间不回收。
- 易错点：压缩payload不等于重编号Slot；原地按错误顺序拷贝会覆盖源记录。
- 整合范围：存储模块内部可独立验收；若与C-E01组合，重跑复用策略及旧RID不复活测试。

## 测试用例

1. `test_rid_stable_after_compact`

   - 输入：五条不同长度记录，删除槽1、3。
   - 必须断言：槽0、2、4的值与RID不变；槽1、3仍删除。

2. `test_compact_free_space`

   - 输入：存活payload总长1000，slot_count=5。
   - 必须断言：free_start=72，free_end=3096，可用3024字节。

3. `test_compact_idempotent`

   - 输入：同一页连续压缩两次。
   - 必须断言：两次最终字节完全相同。

4. `test_compact_corrupt_page_rejected`

   - 输入：活槽越界或重叠。
   - 必须断言：先报格式错误，原页字节不变。
