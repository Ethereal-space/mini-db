# C-B05 BufferPool、pin、dirty、LRU 与 FIFO

## 课程依据

G-P4、G-P5、G-P7；C-S2；D-S8、D-S15、D-S17

课程要求缓存、常用替换策略、命中率和替换日志。方案同时实现LRU/FIFO，默认8帧、测试2帧；pin保护为资源管理约定。

## 任务目标

实现页号到缓存帧映射和统一访问生命周期。fetch时pin，释放时unpin；pin_count不能为负，全部帧被pin时抛BufferFullError。dirty淘汰先成功写回再移除，写回失败必须保留原帧。统计命中、未命中、淘汰和写回次数，记录被淘汰页号、策略及是否写回。

## 预期代码结构解释

- Frame(page_id,data,pin_count,dirty)：内存数据长度固定4096；同一页只能有一个帧。get_page上下文管理器使用try/finally解除pin；调用者显式mark_dirty，不能通过返回拷贝修改后忘记通知。
- LRU/FIFO.choose_victim：仅考虑pin_count=0。LRU在每次成功访问移动到最近端；FIFO只在首次装入时记录顺序，命中不改顺序。被pin的候选暂时跳过但不可被移出内部状态。
- flush_page/flush_all/invalidate：写回成功再清dirty；失败保留dirty。释放页前invalidate要求未pin，丢弃已决定释放页的旧dirty内容，再由DiskManager写FREE头。统计与日志反映真实I/O，不能硬编码预期。
- 易错点：finally解除pin与dirty写回失败保留状态同样重要；仅在正常分支unpin会让一次错误耗尽缓存。
- 整合范围：FakeDisk只用于tests；生产注入真实C-B02。独立跑storage+contracts测试，最终与CLI演示缓存事件。

## 测试用例

1. `test_lru_fifo_a_b_a_c`

   - 输入：容量2，依次访问页A=2、B=3、A=2、C=4，每次访问后解除pin。
   - 必须断言：LRU淘汰3，FIFO淘汰2；两者hits=1、misses=3、evictions=1；日志含准确victim页号。

2. `test_pin_and_exception_release`

   - 输入：同时pin页2、3，再请求4；随后在页2的with块内抛测试异常。
   - 必须断言：请求4为BufferFullError且2/3不被淘汰；异常退出后页2 pin_count归零，可作为候选。

3. `test_dirty_eviction_survives_reopen`

   - 输入：容量1，修改页2并mark_dirty，再请求3，关闭重开。
   - 必须断言：淘汰前write_page(2)恰执行一次；重开页2包含修改；干净页淘汰不产生写回。

4. `test_failed_write_preserves_frame`

   - 输入：页2为dirty且未pin，FakeDisk写页2时抛StorageIOError，再请求3。
   - 必须断言：异常向上传递；页2仍在池内且dirty=True；映射不出现半装入页3。

5. `test_free_invalidates_dirty_cache`

   - 输入：页2缓存含旧脏数据，释放2、重新分配2并写新内容，再flush_all与重开。
   - 必须断言：最终页2仅含新内容；不存在旧帧回写；对仍被pin的页执行释放会失败且不更新free_head。

## 理解考试与小修改

- 讲解题：为什么FIFO命中不更新队列？为什么不能先删除牺牲帧再尝试写回？
- 答案要点：FIFO依据装入先后；若先删帧且写回失败，唯一最新数据丢失，因此提交状态变更必须在I/O成功后。
- 现场小修改：新增只读pinned_pages统计，验证异常退出后为零；不改变LRU/FIFO的既有淘汰结果。
